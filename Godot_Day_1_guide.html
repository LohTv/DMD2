Day 1: build the playable game

Five hours to build the stops, choices, clock, fares and movement. Finish with a game that can reach the destination using a gold marker.

This part includes its own complete Day 1 scripts and uses the original prototype's interface positions. It does not rely on functions hidden in the Day 2 guide. Learn the logic before the exam, using only the reference material your centre permits during it.

The teaching controller asks you to choose each leg separately and leaves out independently moving background vehicles. The original map and interface layout are kept, so you can use your supporting-study screenshots to check placement.

A few Godot terms you need to know

TermMeaning in this game
NodeOne object in the scene tree. A Label displays text; a Button receives a click; an AnimatedSprite2D displays frames.
SceneA saved tree of nodes. The whole game can use one scene called main.tscn.
extends Node2DSays the script controls a two-dimensional node. The data script uses RefCounted because it is a collection of data and helper functions, not an object drawn on screen.
Vector2(x, y)A pair of coordinates. In the map, x grows to the right and y grows downwards.
DictionaryA group of named values, such as {"mode": "train", "cost": 5}. route.cost reads its cost.
ArrayAn ordered list. Indexing starts at zero, so the first stop is stop 0.
preload(...)Loads a resource when Godot loads the script. Here it gives the script access to the data file.
@onreadyWaits until the scene's children exist before looking them up. $UI/Interface/Clock means “find the Clock node at this exact path”.
SignalAn announcement that something happened. The map emits stop_clicked; the main script decides how to respond.
bind(i)Adds an argument to a connected function. Every generated button uses the same choose_route function, but passes its own route index.
deltaThe real seconds since the previous frame. Multiplying by delta prevents a fast computer from making game time run faster.
queue_redraw()Asks Godot to call the map's _draw() function again. Changing a drawing variable by itself does not redraw it.
queue_free()Removes a node safely at the end of the frame. Here it removes old journey buttons.

Make the empty project

  1. Open Godot 4.4. In Project Manager, choose Create, give the project a clear name, and choose an empty folder.
  2. Choose the Compatibility renderer. This is sufficient for a flat 2D map.
  3. Open Project → Project Settings → Display → Window. Set Viewport Width to 1280 and Viewport Height to 800. Use the same window override size if those settings are shown.
  4. Set Stretch Mode to canvas_items. This keeps the canvas coordinates used in this guide while scaling the display with the window.
  5. Create folders called scripts and assets in the FileSystem dock.
  6. If your teacher permits the prepared artwork, have it ready for Day 2 in assets and let Godot import it. In the supplied rehearsal project the path is res://assets/transport_frames.png. Keep your chosen path consistent when assigning textures.
  7. Create a new 2D Scene. Rename its root Main and save it as main.tscn in the project root. Attach scripts/main.gd to Main.
  8. Press F5 and choose this scene as the main scene when asked. F5 runs the project; F6 runs whichever scene is currently open.

Godot node names and file paths must match the code exactly. Wallet and wallet are not the same node name.

Use minutes after midnight

The game stores time as one number, not a string such as “08:37”. This makes addition and comparison easy:

  • 08:00 = 8 × 60 = 480.
  • 08:06 = 480 + 6 = 486.
  • 08:37 = 480 + 37 = 517.
  • 09:30 = 9 × 60 + 30 = 570.

The decimal part represents a fraction of a minute. A clock value of 480.5 is halfway between 08:00 and 08:01. The display rounds down to a whole minute, but scheduling uses the more precise number.

The departure at a later stop is offset from the start of the same service. For example, the 08:10 train takes 24 minutes to reach Zehlendorf Station at 08:34. The helper leg() builds the points array from the two stops and any bend points. For the first connection:

leg(0, 1, "horse", 486, 20, 10, 1,
    PackedVector2Array([Vector2(125, 412), Vector2(165, 393)]))

Read that aloud as: “from zero to one, by horse, first at 486, every 20 minutes, ten minutes of travel, one token, with these two bends”. That sentence is easier to remember than the punctuation alone.

Draw the routes before spending time on geography

Attach map_view.gd to Map. It loads the data, creates the stop labels in _ready(), and uses _draw() for lines and symbols. The complete file is in the code appendix.

  1. Loop through the routes. Draw a thick white line first, then a thinner red horse line or dark train line. The white underneath keeps it readable over coloured land.
  2. Draw walks as short dark dashes. There are two route records for each walk, but only draw it when route.from < route.to. That avoids painting the same dashed link twice.
  3. Loop through the stops. Draw a white-filled red circle for a road stop, or a white-filled dark square for a rail station.
  4. Draw the selected stop with a teal outline and the passenger with a larger gold ring.
  5. Add the text labels using the stop position plus its label offset. Give them a white outline so they remain readable over water and forest.

A stop has a visible radius of about 11 pixels, but its click target has a radius of 22 pixels. The small symbol can stay neat while being easier to click.

Clicks must use the map's coordinates

var mouse: Vector2 = get_global_transform_with_canvas().affine_inverse() * event.position
for index in range(Data.STOPS.size()):
    if mouse.distance_to(Data.STOPS[index].pos) <= 22:
        stop_clicked.emit(index)

The transform converts the mouse event's viewport position into Map's local coordinates, as the original prototype does. The inverse accounts for Map's position and scale. Now the distance check compares coordinates in the same space. Comparing the raw event position directly with a stop position would shift the hit areas by (25, 126).

The full function checks that input is enabled and the event is a pressed left mouse button. Main connects the signal to select_stop. You can temporarily connect it to a small function that prints the index while you build the map, then remove that temporary connection.

Use the same path for the line and passenger

Map creates one Curve2D for each route from its points. There are no curved handles, so the visible bends remain the simple straight segments of the map. Sampling by path length keeps the passenger moving steadily through them:

func position_on_route(index: int, fraction: float) -> Vector2:
    var curve: Curve2D = curves[index]
    return curve.sample_baked(curve.get_baked_length() * clampf(fraction, 0.0, 1.0))

Fraction zero means the start, 0.5 means halfway along the path's length, and one means the end. Do not move directly between the two station coordinates once you have added bends, or the vehicle will cut across the map.

A. Remember what the game needs to store

enum State { READY, WAITING, TRAVELLING, FINISHED }
const START_TIME = 480.0
const DEADLINE = 570.0

B. Connect the scene in _ready()

Connect Map's stop signal to select_stop. Connect the buttons to their matching functions, show the instructions, build the initial journey buttons and update the display. There is no need to make the journey buttons by hand.

map.stop_clicked.connect(select_stop)
$UI/Interface/ShowAll.pressed.connect(select_stop.bind(-1))
pause_button.pressed.connect(toggle_pause)

ShowAll passes −1 because that is the value used for “no destination filter”.

C. Find the next departure

func next_departure(route: Dictionary, at_time: float = -1.0) -> float:
    var now = clock if at_time < 0.0 else at_time
    if route.mode == "walk":
        return now
    var runs = maxi(0, ceili((now - route.first) / route.interval))
    return route.first + runs * route.interval

The calculation asks how many service intervals are needed to reach a departure that has not already passed. ceili rounds upwards. maxi(0, ...) prevents it choosing a departure before the first run.

The optional at_time lets the connections note look ahead to a possible arrival. Calling next_departure(route) uses the current clock; calling next_departure(route, arrival) asks what leaves after that arrival.

  • At 08:05, the first train is still 08:10.
  • At exactly 08:10, that train can still be boarded.
  • At 08:10 plus a fraction of a minute, the next train is 08:40.
  • At Zehlendorf Station at 09:04, use first = 517 and interval = 30: the next train leaves at 09:07, not 09:10.

Walking returns before the interval calculation because its interval is zero. Dividing by a walking interval would cause an error.

D. Select a destination and create the buttons

select_stop(index) first checks that the player is READY, unpaused and not reading instructions. It saves the selected destination, updates Map's selected ring, rebuilds the button list and refreshes the display. Clicking the stop where you already stand clears the destination filter.

rebuild_options() removes the old buttons. It then loops through the routes and keeps only routes whose from equals current_stop. If a destination has been selected, it also keeps only routes whose to matches that destination.

For each remaining route, it creates one Button, stores the route index as metadata, and connects it like this:

button.set_meta("route_index", i)
button.pressed.connect(choose_route.bind(i))
options.add_child(button)

The visible text is refreshed separately. It includes the transport type, destination, departure, arrival and cost. Buttons that cost more than the remaining wallet are disabled. The layout matches the original two-line journey buttons: minimum size (304, 60), font 14, left aligned, inside Scroll/Options. The simpler controller still offers one leg at a time.

Options also contains a Label named Connections, and sometimes a message when no journey is available. When refreshing buttons, first skip any child that is not a Button. Otherwise reading route metadata from a Label will fail. connection_note(stop, at_time) uses the same timetable helper to show onward departures and nearby walking transfers.

Checkpoint: at Potsdam, show all journeys. There should be a horse to Glienicker Bridge and a walk to Potsdam Station. Clicking a faraway stop should not teleport the player or invent a direct route.

E. Reserve the route, then pay when boarding

choose_route(index) checks the current state, origin and budget again. Those checks matter even if the button already looks disabled, because the function is responsible for protecting the game rules.

route_index = index
departure = next_departure(route)
arrival = departure + route.duration

Calculate the departure when the player clicks, rather than using a value the button displayed several seconds ago. After that, departure and arrival remain fixed for this trip.

func board() -> void:
    wallet -= int(routes[route_index].cost)
    state = State.TRAVELLING

This is the only place money is taken. A walk costs zero and boards immediately. If the player cancels before a scheduled departure, there has been no charge to refund.

F. Advance the clock without skipping an event

var rate = 0.12 if state == State.READY else 4.0
var next_time = clock + delta * rate

While deciding, one game minute takes about 8.3 real seconds. Once waiting or travelling, four game minutes pass each real second. Use minf(next_time, departure) when waiting and minf(next_time, arrival) when travelling. This stops the clock exactly at the next event before calling board() or arrive().

This small practice version discards the unused fraction of a frame at an event boundary. It is easier to understand than the existing prototype's full event loop, and the timetable still reaches the exact scheduled event time. It is not intended to simulate hours of transport in one frame.

G. Use the clock to move the passenger

map.progress = clampf((clock - departure) / (arrival - departure), 0.0, 1.0)
map.player_pos = map.position_on_route(route_index, map.progress)

Suppose a leg leaves at 08:10 and arrives at 08:34. At 08:22, 12 of its 24 minutes have passed, so progress is 0.5. Map finds the position halfway along the path. On a horse or train leg, the same value controls a gold route highlight with alpha progress * 0.7, matching the original prototype. Walking uses the ring and a small dark dot instead.

Do not add a separate timer or Tween that moves for a fixed number of real seconds. It would need extra work to stay synchronised when the player pauses or reads Help. Here, stopping the clock automatically stops the passenger's movement.

H. Arrive and show the next choices

arrive() sets current_stop to the route's destination, clears the active route and selection, then checks whether this stop is the goal. If it is not the goal, the state returns to READY and the available buttons are rebuilt.

If the stop is 4, compare clock with 570. At or before 570 is on time. Later is a completed journey that missed the deadline. Reaching station 7 is not a win, because the destination is the city gate.

The player must choose again at intermediate stops. At Zehlendorf Station, for example, they can take the next train or walk to the road stop. Because the clock runs slowly while choosing, they need to respond before the next departure.

I. Keep the display separate from the decisions

update_display() updates text, enabled controls, map variables and the moving gold ring. It does not charge a fare or decide that the player has arrived. Those changes belong to board() and arrive().

The game calls this display function every frame. It updates existing button text, rather than deleting and recreating the buttons every frame. Constant rebuilding would make clicks unreliable and create unnecessary work.

J. Finish pause, help, restart and keyboard controls

func toggle_pause() -> void:
    if not instructions.visible and state != State.FINISHED:
        paused = not paused
        update_display()

Use the complete restart() in the appendix: it resets the wallet, time, selections, marker movement and first-step hint, then rebuilds the choices. Restart returns directly to the map, as in your original prototype. The introduction appears when the project is first opened; How to play opens it again.

Help shows the instruction overlay; closing it hides the overlay. It does not change the paused variable, so a game that was already paused stays paused. The keyboard function handles a new press of Space or R. Enter activates the focused Start journey or Back to game button; there is no H shortcut in the original interface.

func tick_clock(delta: float) -> void:
	var rate = 0.12 if state == State.READY else 4.0

	if state == State.WAITING:

		if clock >= departure:

	elif state == State.TRAVELLING:
		clock = minf(next_time, arrival)
		if clock >= arrival:
			arrive()
	else:
		clock = next_time

	start_button.grab_focus()
	update_display()

func close_help() -> void:
	has_started = true
	instructions.hide()
	start_button.release_focus()
	update_display()

func restart() -> void:
	if instructions.visible:
		return
	state = State.READY
	clock = START_TIME
	wallet = 10
	current_stop = 0
	selected_stop = -1
	route_index = -1
	departure = 0.0
	arrival = 0.0
	paused = false
	first_step = true
	result_text = ""
	last_arrival = "08:00  Journey begins at Potsdam. Reach Potsdamer Tor by 09:30."
	map.selected = -1
	rebuild_options()
	update_display()

func _input(event: InputEvent) -> void:
	if event is InputEventKey and event.pressed and not event.echo:
		if instructions.visible:
			if event.keycode in [KEY_R, KEY_SPACE]:
				get_viewport().set_input_as_handled()
			return
		match event.keycode:
			KEY_SPACE: toggle_pause()
			KEY_R: restart()
			_: return
		get_viewport().set_input_as_handled()

If something breaks, check this before rewriting it

ProblemLikely cause and first check
“Node not found” or a null instance.Compare the scene tree against the @onready path. Check capitals, spelling and parents.
“Cannot infer the type” after reading dictionary data.Use an explicit type, for example var route: Dictionary = routes[index] or var at: Vector2 = stop.pos.
The project cannot load a script or sprite.Check its exact res:// path. Save the file, allow import to finish, and confirm its filename.
The map is visible, but clicks do nothing.Check Interface/decorative Mouse Filters, whether Instructions is visible, and map.input_enabled. The game must be READY.
The click target is shifted away from a stop.Convert event.position with get_global_transform_with_canvas().affine_inverse(), as in the map script; do not compare viewport coordinates with local stop coordinates.
The clock moves while instructions are open.Check the _process() guard and the correct Instructions node path.
A train already gone can still be caught.Recalculate next departure inside choose_route(), not only when the menu was first created.
Every frame reduces the wallet.Move payment into board(). Do not charge inside update_display() or each travel frame.
The passenger cuts across corners.Use position_on_route(). Do not lerp directly from the origin stop to destination once routes contain bends.
The passenger moves, but the gold ring does not.Both should use map.player_pos. Call map.queue_redraw() after setting it.
Journey buttons jump or clicks are missed.Do not rebuild them in every _process() call. Rebuild on selection/state changes and update their text separately.
There is no next-leg button after arrival.Check current_stop, set state back to READY, clear the old selection and call rebuild_options().
The game reports a win at Potsdamer Bahnhof.GOAL must be stop 4, Potsdamer Tor, not stop 7.
Text is clipped or overlaps a button.Check the node's size, font size and wrapping. Container children need appropriate minimum size.

The short version to rehearse without looking

Data: names, coordinates, route times and costs. Draw: lines, symbols and labels. Select: filter journeys from the current stop. Schedule: find the next departure. Wait: advance to that time. Pay: charge once. Move: use clock progress along the route. Arrive: update the stop and either choose again or show the result.

If you can explain each of those actions and point to the function that performs it, you are in a much better position to rebuild and debug the game than if you only recognise the finished code.
